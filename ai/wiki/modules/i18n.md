# `i18n.js`

Two languages: English (source, no-op) and French. ~394 keys in one
`DICT` object (line 11).

## The mechanism

**The key is the exact English string.** There is no namespacing. `t(x)`
returns `x` when `LANG==='en'`, else `DICT[x] ?? x`. A missing key fails
silently to English — which is exactly the failure mode the PO has
complained about repeatedly.

For strings authored bilingually inline, code passes `{en:'…', fr:'…'}`
and `t()` picks the field. `tf()` adds `{0}` templating.

Static DOM text is snapshotted once at boot by `snapshotStatic()` (27),
a TreeWalker storing `[node, originalText]` pairs, excluding
`#recipeList, #log, #cbLog, .log, SCRIPT, STYLE`. `applyStatic()` (36)
always re-derives from the **original** snapshot, so repeated switching
can never compound or duplicate text. `setLang()` (43) persists to
localStorage, sets `<html lang>`, then re-renders the dynamic UI
(`drawLog`, `drawRecipes(true)`, `buildAlloc`, `render(0)`).

## Rules when adding UI text

1. Any new user-visible English string needs a `DICT` entry in the same
   commit. Partial translation is a defect, not a follow-up.
2. Translate as a French writer would, preserving the dry register — not
   word-for-word. The PO has rejected literal renderings by name
   ("plainte d'epaule", "Lire la culture"; approved "Observer la culture").
3. Dynamic text built by concatenation must not concatenate translated
   fragments — use `{en,fr}` objects or `tf()`.
4. If the string is inside an excluded container (`#log`, `#recipeList`,
   `#cbLog`), it will not be caught by `applyStatic()` — it must be
   re-rendered by `setLang()`.

## Audit command

`grep -o "t('[^']*')" ui.js engine.js feel.js` then check each against
`DICT`. Worth running before any release.
